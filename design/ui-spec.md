# Cardputer MPC — UI 规格 v0.2（Gruvbox Dark / SD-aware）

> 目标设备：M5Stack Cardputer-Adv，240×135 IPS，56 键，单声道，microSD。
> 状态：2026-11-08 第二版，已按确认意见改为 Gruvbox Dark，并把 SD 卡状态纳入界面。
> 所有尺寸为 1× 设备像素；`design/out/*.png` 是 4× 最近邻放大。

---

## 1. 画布与网格

| 区域 | Y 范围 | 高度 | 说明 |
|---|---|---|---|
| 顶栏 | 0–11 | 12 px | 6 个页面 tab + BPM + SD 状态 + 电量 |
| 内容区 | 12–123 | 112 px | 每页自定义 |
| 底栏 | 124–134 | 11 px | 当前上下文按键提示 |

- 全部整数坐标，1 px 描边，无圆角 / 渐变 / 阴影 / 抗锯齿。
- 8 px 栅格；文字基线、控件高度尽量取 4 的倍数。

## 3. 字体

- **Silkscreen**（SIL OFL 1.1），只有 8 px 一档；加粗仅用于标题/数值。
- 全大写；字符宽 6 px，一行最多 **40 字符**。
- 数字宽度固定，BPM / 时间 / 电平不会跳动。

## 5. 页面

### 5.1 PAD

```
x=4..122  4×4 垫，28×25，gap 2      x=127..236 右栏
```

- 每垫右下角有缓存标记：`R`（已预载）/ `S`（流式）/ `!`（文件缺失）。
- 右栏：采样名、`A01 0.42S 22K RAM`、波形缩略、VOL/TUNE/CUT/DEC、芯片组。
- 选中垫用外扩 1 px 亮框，可与播放态叠加；播放垫橙框 + 电平条。
- 缺失采样（`!`）仍然可以按，但只发一个静音事件并在底栏提示 `SAMPLE MISSING`。

### 5.2 SEQ

- 8 轨 × 16 步；轨名 3 字符；行 y=24+12r，列 x=25+13c。
- 播放头 = 当前列底色 + 顶部三角；编辑光标 = 白框。
- 力度用橙色深浅表示，4 格一组区分拍。

### 5.3 SMP

- 波形 233×58，中心线，选区外降亮度。
- 起止手柄青色；时间刻度 0.0–0.3；终点由右侧手柄表示。
- NORM / REV / TRIM / SLICE 8 / ZOOM。
- 标题旁显示 `RAM` 或 `STR`，明确这条采样在内存还是 SD 流式。

### 5.4 MIX

- 8 行 × 11 px：轨名、M、S、电平条 104 px、FX 发送 64 px。
- 静音轨名字变暗、电平条变 `ACC_DIM`；独奏 S 高亮。

### 5.5 SYS（系统 + SD 摘要）

- 左列：电量、CPU、内存、VOICES、PADS。
- 右列：`SD READY`、`12.4G FREE`、`1.8 MB/S`、`STALL 0`、MIDI、FW。
- 底部通栏：`UNDERRUN 0`、`LAT 8.2MS`、`POOL 62%`。
- `ENT` 进入 SD 子页。

### 5.6 SD（SYS 2/2）

- 容量条：已用 17.3G / 可用 12.4G。
- 卡信息：`SDHC 32G FAT32 CL10`。
- 吞吐：`READ 1.8 MB/S WRITE 0.9`。
- 健康：`ERR 0 STALL 0 RETRY 0`。
- 缓冲：`BUF 62% STREAM 2/2`。
- 文件：`6 KITS 12 PROJ 34 REC`。
- 操作：`TEST`（测速）、`REMOUNT`、`FORMAT`（红框，二次确认）。

### 5.7 KIT

- 6 行 × 15 px；列：名称、采样数、体积、`RAM/STR/MISS`。
- 选中行整行底色 + 左橙条。
- 右上角显示卡剩余空间。
- `ENT` 载入 → 进入 Loading；`BKS` 删除（二次确认）。

### 5.8 16 Levels（PAD 的模式）

- 按住 `Opt` 进入；垫上显示 1–16 与力度 8–127，颜色随力度加深。
- 右栏：目标垫、力度值、16 段电平条。
- 松开 `Opt` 返回；不做全屏弹窗。

### 5.9 Loading（阻塞态）

- 无 tab，标题栏只显示 `LOADING` 与 SD 状态。
- 进度条、百分比、已读/总量、读速、剩余时间。
- `PRELOAD n / STREAM n` 告诉你哪些进内存、哪些会流式。
- `DO NOT REMOVE CARD` 用黄色警示；`BKS` 取消并回滚到上一个 kit。

### 5.10 No SD（错误态）

- 卡图标 + 红 X，`NO SD CARD`。
- 指引：插入 FAT32 卡；`ENT` 重试；`SYS DIAG` 查看错误码。
- 显示 `MOUNT FAILED ERR 0X0D`，便于上报。

## 6. SD 行为（这一版的重点）

### 6.1 采样缓存策略

| 标记 | 含义 | 触发条件 |
|---|---|---|
| `R` | 常驻 RAM | 采样 ≤ 2 s，且池子放得下 |
| `S` | SD 流式 | 采样 > 2 s，或池子已满 |
| `!` | 缺失 | 清单里有、文件不在卡上 |

- 池子预算 192 KB；套鼓载入时按"短样本优先"填充，剩下的标 `S`。
- 任何采样都不会在音频回调里读 SD；`S` 由存储线程以 500 ms 预读喂给环形缓冲。

### 6.2 卡状态机

```
NO_CARD ──插入──> MOUNTING ──成功──> READY
   ▲                  │失败            │
   └────── ERROR <────┘                │读/写错误
                                      ▼
                                  DEGRADED（只跑 R 采样，S 静音）
```

- 顶栏 `SD` 标记始终反映状态：绿 / 黄（读写中）/ 红。
- `DEGRADED` 时底栏弹一次 `SD LOST · RAM ONLY`，不打断当前 R 采样。
- 卡拔出/挂载失败不得重启，回到 `NO SD` 页即可。

### 6.3 慢卡与满卡

- 载入时测速：`< 1.0 MB/s` 标黄 `SD SLOW`，强制全部预载并降采样到 22.05 kHz；`< 0.5 MB/s` 拒绝流式，只允许 `R`。
- 剩余空间 < 50 MB：KIT 页头变黄；录音前检查，空间不足直接拒绝并提示。
- 测速结果写 NVS，下次启动不必重测（可在 SD 页手动 `TEST`）。

### 6.4 缓冲与欠载

- `BUF %` = 流式环形缓冲的填充率；`< 20%` 黄，`< 10%` 红。
- `STALL` 在 SD 页与 SYS 页都可见；每次音频线程等不到数据 +1。
- 这两个数字是"卡到底行不行"的唯一客观依据，必须上屏。

## 8. 状态

```
AppState
├─ page: PAD | SEQ | SMP | MIX | SYS | KIT | SD | LOADING | NOSD
├─ transport: STOPPED | PLAYING | REC
├─ bank: A..D
├─ selected_pad: 0..63
├─ playing_pads: bitmask(16)
├─ cursor: {track 0..7, step 0..15}
├─ levels_mode: bool
├─ sd: NO_CARD | MOUNTING | READY | DEGRADED | ERROR
├─ buffer: 0..100 %
└─ kit: {name, slots[16], cache[16]}
```

## 9. 动效

- 只有两种：电平条衰减（30 fps）、播放头按 16 分推进。
- Loading 的进度条按实际读盘更新，不做假动画。
- 无页面转场、无淡入淡出。

## 10. 刻意取舍

| 不做 | 原因 |
|---|---|
| 圆角 / 阴影 / 渐变 | 1 px 像素风，省 CPU |
| 16 轨同屏 | 12 px 行高已到可读下限 |
| 全屏弹窗 | 盖住操作对象；用模式 + 底栏提示 |
| 波形缩放动画 | 重绘成本高，用 ZOOM 档位 |
| 卡内文件浏览器 | 先只认 `KITS/PROJ/REC` 三个目录 |
| 力度曲线 | 键盘没有力度，曲线没有意义 |

## 11. 已确认（v0.2）

- 配色：Gruvbox Dark，橙色 `#FE8019` 作主操作色，绿色只表示就绪。
- KIT 保留为第 6 个 tab。
- SEQ 维持 8 轨 × 16 步。
- 全局 8 px 字号。

## 12. 已确认（2026-11-08）

1. **慢卡降级**：`< 1 MB/s` 时自动降采样到 22.05 kHz（v0.3 先测速并显示，降采样在 M3 接入）。
2. **载入策略**：允许"先响前 4 个垫、其余后台继续"（v0.3 为同步载入，M3 改为边载边弹）。
3. **破坏性操作**：删除和格式化都做长按 `Ent` 2 秒确认（v0.3 未提供删除/格式化）。
